# 工作台 UI 与文案审查

日期：2026-10-29。仅审查，未修改产品代码或发布服务。

范围：local-dev 当前工作树，读取既有本地真实快照与历史会话。桌面 1280×720，窄屏 390×844。未重新发起分析、准备提案或写回源。公司当前页面未复验；管理员接入、巡检、完整键盘与读屏流程未覆盖。

## 判断

暖色系统、动态侧栏、独立画布、选区追问、提案与依据的结构已落地。当前更接近换过视觉系统的分析工具，还没有完成成熟业务工作台的信息取舍。剩余的 AI 感主要来自抽象开场、重复解释、通用图形占位，以及把执行记录直接堆到用户界面。

原设计文档顶部仍写“未发布”，与第 12 节的实际发布记录矛盾；历史章节也混有不同轮次边界。它不能直接作为当前完成度清单。

## 文案取舍

以“是否帮助识别对象、理解结果、做下一步决定”为保留标准。空泛的可信宣言直接删除；真实限制保留一次，在会影响判断或动作时出现，不靠满屏免责声明增加可信感。

| 当前表达 | 建议 |
| --- | --- |
| 今天，想看清什么？＋从一个具体的问题开始，让每一步判断都有依据 | 删除价值宣言；首页用业务对象浏览和一个简短输入提示建立入口。 |
| 也可以从这里开始＋还没想好问什么？ | 删除两层前言，保留明确入口。 |
| 当前选区与下方追问范围同步；保存前仍须逐项核对预览 | 删除；选区标签表达前半句，预览确认阶段表达后半句。 |
| 本次分析尚未提供这个对象的改进提案…… | 没有建议时默认显示指标详情；用户主动进入建议空态时才给一行说明和实际可用动作。 |
| 查看建议与状态 | 列表改为“标题与指标不符”等具体摘要，配所属大屏和真实状态。 |
| 核对改动与应用状态＋最近动作记录…… | 合并为一条简洁状态；历史来源按需展开。 |
| 模块标题／业务模块／同名标题 | 默认只显示一次；名称冲突或承担不同业务含义时再展开。 |
| 未提供（反复出现） | 空字段默认隐藏；若缺失会阻断当前判断，集中说明缺少什么及影响。 |
| 提案当时的判断与信息缺口 | 简化为“分析依据”，保留时间和旧版本信息。 |
| 结构示意／未核验……／非真实业务……（多处） | 在画布模式上统一标明“结构预览”；实际数据、源页面与修改预览分清，具体缺失按需展示。 |

## 视觉与交互建议

1. 保留暖白、陶土橙和动态左右栏；橙色集中用于选区与主要动作，图形系列用有辨识度的辅助色。当前浅橙图形、微小标题、浅灰文案共同削弱业务可读性，不能靠增加装饰解决。
2. 画布优先：对象选择放在紧凑切换器；单对象默认跳过列表与分页；任务长文本进对话记录；顶部以当前大屏名和必要状态为主。主画布首屏应能看到完整主要布局，支持适配和按需放大。
3. 真实语义优先：核心卡片显示指标名、单位、可得口径；没有真实数值时用明确缺数状态，不使用 123、65% 这类像结果的数字。地图图形只作构图说明，不能把共用几何轮廓当不同业务的最终主视觉。
4. 依据按任务组织：核心指标先显示单位、口径、来源；模块先显示用途、指标与实际图形。组件构成、通用属性、创建时间后置。保留对象读取契约，不新增平行详情 API。
5. 历史与当前分开：当前对象按正式引用和版本识别，默认显示适用提案；旧轮次和已替代判断单独展开。跨版本同名对象必须可区分，不按名称合并，提案状态仍由既有 API 驱动。
6. 导航收敛：折叠态保留主要工具入口，避免十几个相同会话图标；记录名称用可区分的业务摘要。数据入口逐步从能力说明变成可直接浏览的授权对象；涉及新查询能力先验证现有接口。

## 实施顺序与验收

第一轮：文案与默认状态减法。删冗余引导、空字段、重复标题；只读任务默认依据；无建议隐藏计数与空建议；单对象收起选择列表。验收：同一对象不重复命名，首屏能看主要画布，无无意义引导。

第二轮：工作对象与提案整理。按正式对象、冻结版本和轮次处理同名入口与历史建议；列表增加所属大屏、问题摘要与状态。验收：三张大屏有可区分入口，12 条历史执行不会冒充 12 个当前待改问题，来源仍可追溯。

第三轮：画布与业务详情。修正画布尺寸预算、图形与文本层次，替换虚拟数值占位；指标依据显示真正相关的单位、口径和绑定。验收：1280×720、1440 桌面及窄屏可读；无数据时不暗示有真实结果。

第四轮：数据、设置、巡检与管理员接入逐页整理。管理员和巡检尚未实测，应先补证据再排具体改动；不以本轮用户页面结果推断全部后台现状。

无障碍待验：小字号／低对比度是视觉风险，未测得实际 WCAG 比率；核心区点击目标较小，折叠导航会话图标辨识度低；需补键盘、读屏、200% 缩放、焦点恢复检查。不能以这组截图宣称无障碍验收通过。
