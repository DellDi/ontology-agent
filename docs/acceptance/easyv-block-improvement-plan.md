# C：EasyV 块内内容改造

2026-10-16 用户确认。C 的首个动作确定为：评估业务主题、指标与图形的契合度，提出块内重组方案，用户确认后准确应用到 EasyV，并读回验证。本文记录实施边界与验收状态；实现、真实写回验收及公司部署分别记录。

## 产品边界

- 首期处理已有原型中的普通内容块，保持块外框和业务目标，只改所选块。地图主视觉、核心指标区、动态面板和整屏改造不纳入首期。
- 用户说“这块表达清楚吗？帮我改好”，不需要输入阶段码、工具名或内部标识。
- 判断覆盖主题与指标、指标与图形、整体主次与重复、空间可读性。业务判断展示依据与信息缺口，不包装为已校准的质量分。
- 先复用块内已绑定指标，调整图形与槽位；新增或替换指标必须取得 EasyV 当前可用候选及数据绑定，不能凭名称生成或伪造接通状态。
- 沿用现有只读画布、对象详情和比较呈现，不新增拖拽编辑器、通用工作流或动作配置平台。结构示意不冒充真实效果。

## 交付顺序与验收

| 顺序 | 交付 | 验收 |
|---|---|---|
| 诊断与具体方案 | 读取授权块及全部绑定组件的业务语义；模型依据真实证据提出主题、指标、图形和组合建议；Java 校验引用、数量、图形类别、槽位与尺寸；保存完整提案证据 | 不接受虚构指标、跨块组件、未知方案、无变化和不可行组合；界面展示业务名称、逐项变化及未验证项；仍明确标注尚未应用 |
| 确认与精确执行 | 先以业务身份读取 EasyV 当前目标，验证数据与具体组件，复用现有装配能力生成明确的待应用块；保存该结果和目标状态，展示真实预览后再由用户确认；确认后准确保存 | 生成与组件选择发生在确认前；不把提案转成自然语言重新选型；重复提交不重复改造；过期、无权、失败和结果未知分别记录；模型不能直接触发写入 |
| 保存后复验 | 读回保存的原型，逐项核对指标、图形、位置和目标块外内容，打开真实 EasyV 预览；保留前后证据和执行结果 | 真实保存与实际呈现均有证据；部分失败不报成功；不把结构适配分提升称为业务质量认证 |

## 现有能力与缺口

- 平台已有对象读取、业务语义、方案库、空间适配评估、有限工具编排及调用证据保存，可以复用。
- EasyV 源代码已有换图形、换指标、换主题与块内布局切换。当前聊天调度会重新识别和选型，不能作为“准确应用已确认提案”的直接替代。
- EasyV 的精确执行入口、业务身份授权和跨系统调用已实现。平台通过独立内部接口凭据调用源服务，不复用只读采集账号，不直接更新源库或平台 facts；真实写回与呈现验收仍须单独通过。
- 数据字段、维度、真实数值分布和组件具体支持尚不能由现有冻结语义完整证明。图形变化在执行前须用实时目标校验，不能仅凭指标名称判定可执行。
- EasyV 原型与执行上下文存在多个消费者；执行入口必须同时维护其现有真相，不允许只改原型 JSON，导致下一次聊天或保存覆盖改造。
