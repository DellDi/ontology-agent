2026-10-19，用户确认：业务源项目原则上不改造，动作可以经外部工具、函数或数据库适配器执行。本次在 ontology-agent 内替换执行实现；EasyV 独立分支的提交只保留为历史参考，不再作为合并或发布依赖。

## 当前实现

沿用 `EasyVBlockActionPort.prepare/apply`、应用服务、V32 动作记录和既有页面。模型仍只产出提案；准备阶段读取实时目标、验证业务身份和当前方案，生成明确的前后结果；登录用户确认后才写入。页面与历史记录契约不变，没有增加另一套执行器或工具注册中心。

`EasyVBlockActionDatabaseAdapter` 使用单独、默认关闭的目标 PostgreSQL 与 Redis 连接，与平台主库、只读采集连接隔离，不向 Spring 注册第二个主库 JdbcTemplate 或 RedisTemplate。没有新增源库表或迁移，不使用旧的 `EASYV_ACTION_BASE_URL/TOKEN`。

保存顺序：

1. 重新核对实时 `ai_screen_app` 的所有者、空间、团队及删除状态；冻结分析权限不替代实时写入权限。
2. 在源库事务内锁定应用、原型和当前持久编辑快照，核对原型前态及实时方案/图形支持；只写已准备并确认的结果。实时区域尺寸继续使用现有适配校验，不放宽阈值。
3. 同一事务更新 `ai_screen_prototype` 的原型及更新时间，与 `ai_pipeline_node_record` 最新 PipelineCompleted 中的目标块编辑投影；其他原型内容、XML、模板、生成任务和快照字段保持。上下文更新失败时原型一起回滚。
4. 完整读回并提交事务，随后删除源 Redis 的 `ai:screen:regen:<generationTaskId>`。源端现有加载逻辑会从最新持久编辑快照恢复，无需新增 EasyV 接口。
5. Redis 失效失败时记录 `context_pending`，明确数据库已经保存；恢复同一动作只补缓存失效，不再次更新原型。数据库结果不明保留 `unknown`，并发变化明确拒绝，不自动重新规划或覆盖人工编辑。

原型变换和编辑投影放在领域层 `PrototypeBlockWriteback`；SQL、事务和 Redis 位于出站适配器。图形翻译实时读取 `ai_chart_type_mapping`，槽位读取现有方案与类型表，不增加行业英文名枚举或重复的图形映射配置。

## 连接与启用

在执行动作的 Java API 进程配置以下环境变量；只读采集 Worker 不需要该连接。启用前核对连接所属的同一 EasyV 环境，尤其 Redis 实例和逻辑库，不能把平台 Redis 当作业务源 Redis。

| 配置 | 用途 |
|---|---|
| `EASYV_ACTION_ENABLED` | 默认 `false`；显式开启写回 |
| `EASYV_ACTION_JDBC_URL` | 业务源 PostgreSQL JDBC URL，不是平台库 |
| `EASYV_ACTION_USERNAME` / `EASYV_ACTION_PASSWORD` | 业务源写回连接身份，与平台登录和 EasyV 用户绑定分别维护 |
| `EASYV_ACTION_SCHEMA` | 默认 `easyv_saas`，只允许合法 schema 标识符 |
| `EASYV_ACTION_REDIS_URL` | 同一业务源使用的 Redis，含实际逻辑库；支持 redis/rediss |

数据库连接需要读取应用、原型、PipelineCompleted 编辑快照、方案、槽位类型和图形映射；写入仅涉及原型 JSON/更新时间及编辑快照 output。适配器不接受任意 SQL、表名或模型生成的字段路径。凭据仅在部署环境注入，不提交真实值；仅有数据库编辑角色仍不能跳过平台登录、应用所有者绑定和用户确认。

## 给 D 阶段的复用边界

当前公共基础是“提案/准备/确认/执行状态/审计 + 动作端口 + 连接隔离”，现有工具和页面已经是实际调用者。D 的管理入口应调用同一应用服务，展示接入状态、动作记录、失败与恢复；不能另写一套直接执行 SQL 的管理逻辑。

后续出现第二个真实接入时再扩展 API 或外部函数实现，按其协议复用端口与执行生命周期。本次不增加通用适配器注册表、脚本上传、在线凭据编辑、任意 SQL 工具或跨领域动作公共契约。D 的自动采集发布与本次用户确认写回是不同任务，不能据此开启无人确认的自动业务修改。
